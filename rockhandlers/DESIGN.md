# rockhandlers — устройство и решения

Документ описывает, как устроен `rockhandlers` и почему он устроен именно так. API для пользователя — в [README](README_RU.md), руководство для авторов транспортов — в [TRANSPORT_RU.md](TRANSPORT_RU.md).

## 1. Назначение

`rockhandlers` — форма обработки запроса, не зависящая от технологии: цепочка шагов с `Next`, типизированные параметры и результат, Locals, middleware, перехват паник, виды ошибок, отмена. То же, что во Fiber дают `Ctx`, `Next`, `Locals`, ErrorHandler и recover, только одинаково для HTTP, очередей, cron и CLI.

Граница с транспортом (App):

| `rockhandlers` | Транспорт |
|---|---|
| цепочка: middleware → разбор (`fill`) → `Validate` → шаги | принять обращение своего протокола |
| перехват паник везде, включая `fill` | заполнить `Params` в `fill` |
| виды ошибок, `Canceled` / `Timeout` из контекста | перевести `Result` и вид ошибки в ответ протокола |
| Locals, middleware, `Timeout` | жизненный цикл, остановка, параллельность, лимиты, протокольные middleware |

Правило для спорных случаев: «имеет ли это смысл на другом транспорте?» Если нет — это транспорту.

## 2. Ctx и шаги

```go
type Handler[P, R any] func(c *Ctx[P, R]) error

type Ctx[P, R any] struct {
    Params P // заполнил транспорт; не nil
    Result R // создан до цепочки; шаги его заполняют; не nil
    // ...
}
```

- `P` и `R` — **указатели на структуры** (`*CreateParams`). Поэтому интерфейсы-ограничения работают с методами на указателе. `Chain` проверяет это при сборке и паникует на старте.
- **`Ctx` реализует `context.Context`, а не встраивает его.** Иначе `SetContext` и `Timeout` подменяли бы контекст сами на себя и уходили в бесконечную рекурсию. Текущий контекст — `Base()`, замена на остаток запроса — `SetContext(ctx)`.
- Метод `c.Done()` — канал контекста. Переменная `rockhandlers.Done` (§3) — сигнал успешного раннего выхода. Это разные вещи с одинаковым именем: метод и переменная пакета не конфликтуют.
- **Новый `Ctx` на каждый вызов, без пула.** Его безопасно захватывать, но он не потокобезопасен.

## 3. Семантика цепочки

Звенья: middleware (внешние → внутренние) → `prepare` (`fill` + `Validate`) → шаги.

1. **Звено вернуло `nil` и само не вызвало `Next` — цепочка продолжается автоматически.** Забытый `Next` — самая частая ошибка во Fiber: цепочка молча обрывается, и клиент получает наполовину заполненный результат. Здесь такой ошибки нет.
2. **Звено вызвало `Next` само — повторного запуска нет.** Повторный `Next` из того же звена возвращает результат первого вызова. `Next` после последнего шага возвращает `nil`.
3. **`return rockhandlers.Done` — успешный ранний выход.**
   - Следующие звенья не запускаются.
   - Внешние звенья получают из своего `Next` значение `nil`.
   - `Serve` и `Run` возвращают `Result` и `nil`.
   - `Done` никогда не выходит наружу.
   - Middleware, вернувший `Done` до шагов, пропускает и валидацию, и шаги.
4. **Ошибка** звена возвращается внешним звеньям через их `Next` и выходит из `Serve`. `Result` при этом отбрасывается.
5. **Паника** в любом звене, включая `fill`, становится `Internal` с `*PanicError{Value, Stack}`. Внешние middleware видят её как обычную ошибку.
6. **Отмена:** `Next` не запускает следующее звено, если контекст уже завершён, и возвращает ошибку контекста (`Canceled` / `Timeout`). Внутри звена отмена кооперативная: шаг передаёт `c` в блокирующие вызовы. Горутин на шаг нет, брошенных шагов нет.

Реализация: у `Ctx` есть индекс текущего звена и для каждого звена флаги «запущено» и результат. После `run(i)` проверяется: если звено вернуло `nil`, `Done` ещё не было и `i+1` не запускалось — вызывается `Next`. `Done` превращается в `nil` в том `Next`, который запустил вернувшее его звено, и выставляет флаг `done`, чтобы внешние звенья не продолжили цепочку.

## 4. Параметры, проверка, разбор

- **Если `Params` реализует `Validate() error`,** проверка выполняется сразу после `fill`, до первого шага: сначала проверяем, потом используем. Простая ошибка из `Validate` → `Invalid` с её текстом: этот текст пишет автор обработчика. `*Error` проходит как есть.
- **`fill` выполняется внутри цепочки, после middleware.** Поэтому middleware видят ошибки разбора, а `Timeout` покрывает и разбор.
- **Простая ошибка из `fill` → `Invalid` с общим сообщением «invalid request»,** а сама ошибка остаётся причиной для логов. Текст декодера (`cannot unmarshal string into Go struct field CreateParams.qty`) называет Go-типы и поля, поэтому клиенту его не показываем. Транспорт, который хочет сказать точнее, возвращает из `fill` `*Error` с безопасным текстом и, при желании, `Fields`.

## 5. Переиспользуемые шаги: ограничения вместо приведений

Шаг, которому нужны данные запроса, объявляет требование интерфейсом-ограничением. Параметры выполняют его встраиванием:

```go
type TokenParams interface{ BearerToken() string }

func Bearer[P TokenParams, R any](c *rockhandlers.Ctx[P, R]) error { /* c.Params.BearerToken() */ }
```

- **`Chain("x", Bearer, create)`** выводит `P` и `R` из конкретного шага (Go 1.21+) и инстанцирует дженерик-шаг. Если модель не встраивает нужную структуру, это ошибка компиляции.
- **В интерфейсе `Context` для middleware нет доступа к `Params` и `Result`.** Если нужны данные — это шаг, а не middleware.
- **Группы — обычные дженерик-функции** с `Prepend`: у методов в Go не бывает своих параметров типа.

## 6. Locals

`NewLocal[T](name)` — типизированный ключ, сравнивается по указателю. Значения хранятся в `Ctx` и живут один запрос. `MustGet` паникует, если значение не положили: это ошибка сборки цепочки, она становится `Internal`.

## 7. Ошибки

```go
type Error struct {
    Kind    Kind
    Message string            // для клиента
    Fields  map[string]string // ошибки по полям
    Err     error             // причина, только для логов
}
```

| `KindOf(err)` | Когда |
|---|---|
| `KindNone` | `err == nil` — чтобы `switch KindOf(err)` в транспорте покрывал и успех |
| вид из `*Error` | бизнес-ошибка: `Invalid`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`, `Unavailable` |
| `KindCanceled` | `context.Canceled` |
| `KindTimeout` | `context.DeadlineExceeded` |
| `KindInternal` | всё остальное, паники |

`MessageOf` для `Internal` возвращает пустую строку: транспорт показывает свой общий текст. Перевод вида в протокол — решение транспорта.

## 8. Контракт для транспорта

```go
func (r Route) Serve(ctx context.Context, fill func(params any) error) (any, error)
func (r Route) With(mws ...Middleware) Route
func (r Route) Name() string
func (r Route) ParamsType() reflect.Type
func (r Route) ResultType() reflect.Type
```

- `Chain` стирает дженерики, поэтому `Route` — обычное значение: маршруты разных типов лежат в одном слайсе (`[]rockhttp.Endpoint`).
- `Serve` создаёт новый `P` и отдаёт его в `fill`. Транспорту не нужно знать тип параметров.
- **`Serve` никогда не паникует.** При ошибке результат — `nil`, наполовину заполненный `Result` не утекает. При успехе результат — `R`.
- `With`: первый middleware — внешний, каждый следующий `With` оборачивает всё, что было добавлено раньше. Так транспорт добавляет свои middleware при регистрации.
- `ParamsType` и `ResultType` нужны для проверок на старте — например, отказать типу результата, который транспорт не умеет отдавать.

## 9. Тестирование

```go
res, err := rockhandlers.Run[*CreateResult](ctx, Create, &CreateParams{...})
```

**Порядок параметров типа — `Run[R, P]`, а не `[P, R]`.** Go разрешает явно указывать параметры типа только слева направо. Если `R` стоит первым, его указывают, а `P` выводится из аргумента `params`. При порядке `[P, R]` пришлось бы писать оба. `Run` проверяет, что `P` и `R` совпадают с маршрутом, и проходит всю цепочку: middleware, проверку параметров, шаги.

## 10. Вне слоя

- **Транспорту:** стриминг (SSE, WebSocket), повторы, DLQ, prefetch, лимиты параллельности, протокольные middleware (CORS, gzip).
- **Приложению или каталогу:** готовые шаги и middleware — авторизация, тенант, кэш, логирование, request id.

## Решения

| Решение | Почему |
|---|---|
| Цепочка шагов, а не одна функция `func(ctx, *In) (*Out, error)` | шаги и middleware переиспользуются, ранний выход и общая обвязка выражаются естественно |
| `Params` и `Result` — поля `Ctx`, а не Locals | типизированы и есть всегда |
| Ограничения-интерфейсы вместо `Params() any` в middleware | ошибки ловит компилятор, нет приведений типов |
| Звено без `Next` продолжает цепочку, ранний выход — `Done` | забытый `Next` не обрывает цепочку молча |
| Общий текст «invalid request» для ошибок `fill` | текст декодера раскрывает внутренние имена |
| Кооперативная отмена без горутин на шаг | брошенный шаг гоняется с записью в `Result`; убить горутину в Go нельзя |
| Статус успеха HTTP задаётся при привязке (`rockhttp.Endpoint.Status`) | статус — понятие HTTP, а не бизнеса |

## Открытые вопросы

1. **Динамический статус успеха** — например, «создано» → 201, «уже было» → 200. Сейчас статус задаётся статически при привязке. Вариант — результат реализует `HTTPStatus() int`, но это затаскивает HTTP в модели. Делать только при реальной потребности.
2. **Request id и трассировка** — готовый middleware или шаг. В ядре его нет, кандидат для каталога.
